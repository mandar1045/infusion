# Soak test: watchers against real APIs

A long-running test of `Infusion.Runtime.Watch` against GitHub and CoinGecko,
with SDKs generated by Infusion from the vendors' own OpenAPI specs.

## What it checks

Five watchers run under a supervisor (`async: true`), each sending its events
to a replica that rebuilds the list from events alone:

| Watcher | List | Why |
|---|---|---|
| `vscode_recent` | microsoft/vscode issues and PRs, most recently updated first, page 1 | heavy churn, a partial view |
| `vscode_open_prs` | every open microsoft/vscode PR (about 3,200, 32 pages), `version: "updated_at"` | scale: deletes, pages shifting while they are read |
| `elixir_open_issues` | elixir-lang/elixir open issues | a quiet list: 304s |
| `phoenix_open_prs` | phoenixframework/phoenix open PRs | a small complete list |
| `coingecko_top100` | CoinGecko's top 100 coins | another API, changing every minute |

Every 10 minutes a checker fetches each list directly, not through the
watcher, and compares it with the replica. A difference seen in two checks in
a row while the real item stayed the same is a **missed change**. Other
differences are timing: the list changed between the watcher's poll and the
checker's fetch.

Everything is logged as JSON lines in `data/`: every event (with how long
after the item's own `updated_at` it arrived), every poll (pages, 304s),
every check, requests per status each minute, VM memory each minute, and
GitHub's rate-limit counter every 5 minutes.

## Run it

```console
$ ./setup.sh
$ GITHUB_TOKEN=... mix run --no-halt
$ elixir report.exs    # any time: writes REPORT.md from data/
```

GitHub's spec declares no auth, so `config/config.exs` sends `GITHUB_TOKEN`
as a bearer token. The rate-limit counter is per account, so other tools using
the same token show up in it.

## What it found

Running it found four bugs in `infusion_runtime`, all fixed in 0.2.0 and
0.2.1, each with a test that reproduces it:

1. A supervised watcher whose first poll failed (GitHub's rate limit) stopped
   the application from starting. Fixed with `async: true`.
2. One push to microsoft/vscode made all 3,186 open PRs look updated, through
   the repository embedded in every PR. Fixed with `version: "updated_at"` and
   nested `ignore:` paths.
3. A watcher on those PRs held 320-370 MB; now about 14 MB, measured on the
   same 32 pages. Items are kept compressed instead of as decoded terms, whose
   strings also pointed into (and kept alive) every page body.
4. Pages shifted while they were read (PRs merged on page 1), so two PRs open
   since November 18 fell between pages and were reported as created.
   Deletes on multi-page lists now need two reads to confirm, and items
   older than the watcher are `:entered`, not `:created`.
